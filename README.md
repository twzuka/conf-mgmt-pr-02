# Граф зависимостей пакетов NuGet

Консольный инструмент визуализации графа зависимостей для менеджера пакетов
NuGet (.NET). Готовые менеджеры пакетов и библиотеки для получения
зависимостей не используются.

Проект разработан в рамках практической работы № 2 по дисциплине
«Конфигурационное управление».

- **Группа:** ИКБО-40-25
- **Вариант:** 13
- **Реализован:** этап 1 — минимальный прототип с конфигурацией.

## Требования

- Python 3.9 или новее.
- Windows или Linux.
- Библиотека PyYAML для чтения конфигурации:

```bash
pip install -r requirements.txt
```

## Быстрый запуск

Все команды выполняются из корня репозитория. Единственный аргумент —
путь к YAML-файлу конфигурации; по умолчанию используется `config.yaml`.

### Linux

```bash
./run.sh config.yaml
```

### Windows

```powershell
.\run.bat config.yaml
```

Без скриптов: `python src/main.py config.yaml`.

## Настройки

Все параметры задаются в конфигурационном файле формата YAML. Каждый из
шести параметров обязателен, неизвестные параметры считаются ошибкой.

| Параметр | Тип | Назначение |
|---|---|---|
| `package` | строка | Имя анализируемого пакета, например `Serilog` |
| `repository` | строка | URL репозитория или путь к файлу тестового репозитория |
| `test_mode` | `true` / `false` | Режим работы с тестовым репозиторием |
| `version` | строка | Версия пакета, например `"8.0.0"` или `"1.0.0-beta"` |
| `output_image` | строка | Имя файла с изображением графа, расширение `.png` |
| `ascii_tree` | `true` / `false` | Вывод зависимостей в виде ASCII-дерева |

Пример (`config.yaml`):

```yaml
package: Microsoft.Extensions.Logging
repository: https://api.nuget.org/v3/index.json
test_mode: false
version: "8.0.0"
output_image: graph.png
ascii_tree: true
```

Правила проверки:

- `package` — непустая строка до 100 символов из латиницы, цифр, `_`,
  разделённых `.` или `-`.
- `repository` — при `test_mode: false` URL с протоколом `http` или
  `https`; при `test_mode: true` путь к существующему файлу. Относительный
  путь отсчитывается от каталога, в котором лежит файл конфигурации.
- `version` — версия NuGet: от двух до четырёх чисел через точку,
  необязательные суффиксы `-метка` и `+метаданные`. Версию нужно писать в
  кавычках: без них YAML прочитает `3.1` как число, и программа сообщит
  об этом.
- `output_image` — имя файла с расширением `.png`; каталог для файла
  должен существовать.
- `test_mode` и `ascii_tree` — только логические значения `true` или
  `false`.

## Функции

| Модуль | Функция | Назначение |
|---|---|---|
| `src/main.py` | `main` | Точка входа, возвращает код завершения |
| | `parse_args` | Разбор аргументов командной строки |
| | `format_value` | Преобразование значения в строку; логические значения выводятся как `true` или `false` |
| | `print_config` | Вывод параметров в формате `ключ: значение` |
| | `report_errors` | Вывод всех ошибок конфигурации в stderr |
| `src/config.py` | `load_config` | Чтение и проверка файла, возвращает `Config` |
| | `read_text`, `parse_yaml` | Чтение файла и разбор YAML |
| | `describe_yaml_error` | Формирование сообщения об ошибке YAML с номером строки и столбца, если они известны |
| | `check_keys` | Поиск отсутствующих и неизвестных параметров |
| | `validate_values` | Проверка всех значений с накоплением ошибок |
| | `require_text` | Проверка непустой строки и удаление пробелов по краям |
| | `check_package`, `check_version` | Проверка имени и версии пакета |
| | `check_repository` | Проверка URL или файла тестового репозитория |
| | `check_url` | Проверка протокола HTTP(S) и наличия сетевой части URL |
| | `check_test_repository` | Проверка существования тестового файла; относительный путь отсчитывается от каталога конфигурации |
| | `check_output_image`, `check_flag` | Проверка имени PNG и флагов |

| | `Config.items` | Возврат пар «ключ — значение» в установленном порядке параметров |
| | `ConfigError.__init__` | Сохранение списка проблем и формирование сообщения исключения |

Коды завершения: `0` — успех, `1` — ошибка конфигурации. Если ошибок
несколько, программа перечисляет их все за один запуск.

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Набор конфигураций для демонстрации ошибок лежит в `tests/configs/`:

| Файл | Ошибка |
|---|---|
| `bad_syntax.yaml` | Синтаксическая ошибка YAML |
| `not_mapping.yaml` | Корень файла не словарь |
| `missing_keys.yaml` | Не заданы обязательные параметры |
| `unknown_key.yaml` | Неизвестный параметр |
| `empty_package.yaml`, `bad_package.yaml` | Пустое или недопустимое имя пакета |
| `bad_url.yaml` | Адрес репозитория без протокола |
| `missing_repo_file.yaml` | Нет файла тестового репозитория |
| `bad_test_mode.yaml`, `bad_ascii_tree.yaml` | Не логическое значение |
| `bad_version.yaml`, `numeric_version.yaml` | Неверная версия или версия без кавычек |
| `bad_image.yaml` | Файл изображения не `.png` |
| `many_errors.yaml` | Ошибки в пяти параметрах сразу |

## Примеры использования

Корректная конфигурация:

```text
$ ./run.sh config.yaml
package: Microsoft.Extensions.Logging
repository: https://api.nuget.org/v3/index.json
test_mode: false
version: 8.0.0
output_image: graph.png
ascii_tree: true
```

Тестовый режим:

```text
$ ./run.sh tests/configs/valid_test_mode.yaml
package: A
repository: tests/repos/simple.txt
test_mode: true
version: 1.0.0
output_image: graph.png
ascii_tree: true
```

Ошибки:

```text
$ ./run.sh tests/configs/numeric_version.yaml
Ошибка конфигурации:
  - version: версия 3.1 прочитана как число; заключите её в кавычки, например "8.0.0"

$ ./run.sh tests/configs/many_errors.yaml
Ошибка конфигурации:
  - package: ожидается строка, получено int (42)
  - repository: 'ftp://example.org' не является URL вида https://host/...
  - version: 'latest' не похоже на версию NuGet (ожидается 1.2.3 или 1.2.3-beta)
  - output_image: значение не должно быть пустым
  - ascii_tree: ожидается true или false, получено 'maybe'
```
